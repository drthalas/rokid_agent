# ALE-464 diagnostic session cleanup plan

This phase is read-only for existing sessions. Run `node scripts/diagnostic-audit.mjs --dry-run` from the repository root. It starts its own loopback app-server, pages through visible threads, and prints only ID, validated diagnostic name, temporary cwd basename and status for candidates. It does not print conversation previews or inspect production gateway state. The temporary directory inventory is a count and a bounded sample of names; no directory contents are read or removed.

Review every candidate against native thread details and current tasks before any later mutation. `rokid-test-*` cwd alone is insufficient ownership proof: those rows remain `hold-for-review`. A matching diagnostic name plus matching temporary cwd yields `archive-candidate-review`, still requiring manual review. Active sessions and ambiguous sessions stay untouched. Keep all production Jarvis threads and sessions containing unresolved evidence. The current ALE-462, ALE-470 and ALE-466 sessions stay active. For completed or superseded development sessions whose evidence is captured in Git/Linear/specs, archive after their owners have released them.

For confirmed old diagnostic threads, first archive with native `thread/archive`; consider native `thread/delete` only in a separately authorized cleanup after ownership and connected-app data have been checked. Deletion is irreversible. A missing temporary cwd does not invalidate a thread record. For stale `rokid-test-*` directories, verify no process uses the cwd and inspect only for the expected fixture shape before a separately authorized deletion. Never copy complete failed-run directories or credentials into an archive. Successful fixture runs already remove their temporary directory in `finally`; future failed-run evidence should be compact, sanitized and bounded before any retention is added.

The root and history restart smokes create named durable diagnostic threads to test continuity, then archive them with a new owned app-server after the original is closed. Ordinary smoke harnesses use the trusted local `ephemeralThreads` flag. The flag is absent from the public gateway request API and production defaults to durable threads.

Read-only inventory on 2026-10-04: 99 visible threads scanned, 25 cwd-only diagnostic matches held for review, and 573 matching temporary directories counted. None qualified for automatic action. No old thread or directory was archived or deleted in this phase.
